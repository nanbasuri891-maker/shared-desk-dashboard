プロンプト：センチメント分析

正本：GitHub shared-ai-workspace の agents/プロンプト_センチメント分析.md（ブランチ ai/20261030-routing-goal）。このページは共有範囲の写しです。更新日時：2026-11-01 10:10 JST

センチメント分析（Sentiment Analysis）とは、テキスト（文章・レビュー・投稿など）に込められた感情や態度を、コンピュータで自動的に判定する技術です。

主に「ポジティブ（肯定的）」「ネガティブ（否定的）」「ニュートラル（中立）」の3つに分類することが多いですが、より細かく「喜び」「怒り」「悲しみ」「驚き」などの感情に分ける場合もあります。

主な目的

  • 顧客の声（レビュー、アンケート）の傾向を把握する
  • SNS上の評判や炎上の度合いをリアルタイムで監視する
  • ブランドや商品に対する世間の印象を数値化する

よく使われる手法

  1. ルールベース
    あらかじめ用意したポジティブ/ネガティブ単語の辞書を使って判定するシンプルな方法。

  2. 機械学習・深層学習
    大量のラベル付きデータで学習させたモデル（BERTなどの大規模言語モデルを含む）を使い、文脈を考慮して判定する。現在の主流。

  3. ハイブリッド
    ルールと機械学習を組み合わせる方法。

具体例

  • 「この商品は本当に使いやすくて最高！」 → ポジティブ
  • 「期待していたのに全然ダメだった…」 → ネガティブ
  • 「普通の品質だと思います」 → ニュートラル

主な活用分野

  • マーケティング（顧客満足度の分析）
  • SNSモニタリング
  • 株価予測（ニュースやSNSの感情から市場の空気を読む）
  • カスタマーサポートの優先順位付け

簡単に言うと、「文章の“感情の色”をコンピュータに読み取らせる技術」です。 センチメント分析は、さまざまな業界・業務で「人の感情を数値化・可視化する」ために実際に使われています。代表的な活用例を具体的に挙げます。

1. マーケティング・顧客理解

  • 商品レビュー分析
    Amazonや楽天、Googleレビューなどの大量の口コミを自動でポジティブ／ネガティブに分類し、「どの機能が好評か」「どこが不満か」を瞬時に把握。
  • キャンペーン効果測定
    新商品発売後のSNS投稿やアンケート回答の感情傾向を追うことで、「好意的に受け止められているか」「炎上の予兆はないか」をリアルタイムで確認。
  • 顧客満足度（CS）の定量化
    NPS（ネットプロモータースコア）調査の自由記述部分を分析し、数値だけでは見えにくい「理由」を抽出。

2. SNS・オンラインレピュテーション管理

  • ブランド監視（ソーシャルリスニング）
    Twitter（X）やInstagram、掲示板などで自社ブランド名・商品名がどう語られているかを24時間監視。ネガティブ投稿が急増したらすぐアラートを出す。
  • 炎上対策
    投稿の感情スコアが急激に下がったタイミングを検知し、早期対応（謝罪文の準備や削除依頼など）を可能にする。
  • インフルエンサー選定
    投稿の感情傾向がポジティブで、かつ自社ブランドと親和性が高いアカウントを自動でリストアップ。

3. カスタマーサポート・問い合わせ対応

  • 優先順位付け
    問い合わせメールやチャットの文章を感情分析し、「怒っている顧客」や「緊急度が高い苦情」を優先的に対応。
  • オペレーター支援
    会話中の顧客の感情変化をリアルタイムで表示し、トーンを合わせた対応をサポート。
  • FAQ改善
    ネガティブな問い合わせが多いトピックを抽出し、説明文やマニュアルを改善。

4. 金融・投資

  • 市場センチメント分析
    ニュース記事やSNSでの企業・銘柄に関する投稿の感情を集計し、「市場の空気」を数値化。株価予測モデルの補助指標として利用される。
  • リスク管理
    ネガティブニュースが急増した銘柄や業界を早期に検知。

5. 人事・組織マネジメント

  • 従業員エンゲージメント調査
    匿名アンケートの自由記述を分析し、「どこに不満が溜まっているか」「どの施策が好評か」を把握。
  • 退職リスクの予兆検知
    社内チャットや1on1のメモから、ネガティブ感情の高まりを検知する試みもある（プライバシーへの配慮が重要）。

6. 政治・公共分野

  • 世論調査の補完
    SNS上の政策・政治家に関する投稿の感情分析で、従来の世論調査では見えにくいリアルタイムの反応を把握。
  • 災害時の情報分析
    被災者の投稿から「不安・怒り・希望」などの感情を抽出し、必要な支援の優先順位を判断する材料にする。

7. その他の面白い活用例

  • 映画やドラマの視聴者反応をリアルタイム分析して、次回作や宣伝戦略に反映
  • ゲームのレビューやフォーラム投稿から、アップデートで改善すべきポイントを抽出
  • ホテルや飲食店の口コミを分析して、サービス改善ポイントを可視化

要するに、「人が書いたテキストに込められた感情を、人間が読むより速く・大量に・客観的に把握したい」という場面で広く使われています。
特に最近は、大規模言語モデル（BERTやGPT系）の登場で精度が大きく上がったため、以前は難しかった「文脈を考慮した細かい感情分析」も実用レベルになっています。

はい、その部分についてもう少し詳しく説明します。

以前はなぜ難しかったのか

従来のセンチメント分析には大きく2つの壁がありました。

  1. 文脈の理解が苦手 - ルールベースや古典的な機械学習（SVM、ナイーブベイズなど）は、単語の出現頻度や単純な共起関係に頼っていました。 - 例：「この映画は予想外に面白くなかった」
    → 「面白く」というポジティブ語があるため、誤ってポジティブと判定してしまうことが多かった。 - 「全然ダメじゃない」のような否定表現や皮肉も正しく扱えませんでした。

  2. 細かい感情の分類が粗い - 多くのモデルは「ポジティブ／ネガティブ／ニュートラル」の3分類が限界。 - 「喜び」「怒り」「失望」「驚き」「安堵」など、より細かい感情や、どの部分に対する感情か（aspect-based）を捉えるのは非常に困難でした。

なぜ今は「実用レベル」になったのか

主に大規模言語モデル（LLM）とTransformerアーキテクチャの登場が決定的でした。

  • BERT（2018年）以降の事前学習モデル
    大量のテキストで「文脈を考慮した単語の意味」を事前に学習しているため、否定・皮肉・曖昧な表現をかなり正確に理解できるようになりました。

  • 感情の細分化が容易に
    「ポジネガ」だけでなく、

  • 喜び・怒り・悲しみ・恐れ・驚き・嫌悪（Ekmanの基本感情）

  • さらに細かい「安堵」「失望」「期待」「皮肉」など
    をマルチラベルやマルチクラスで扱えるようになりました。

  • Aspect-Based Sentiment Analysis（観点別分析）が実用化
    「この商品はデザインは最高だけど、バッテリー持ちは最悪」のように、
    文章の中でどの対象（aspect）に対してどんな感情かを同時に判定できるようになりました。
    これがマーケティングやレビュー分析で特に強力です。

  • ゼロショット・フューショットの精度向上
    大量のラベル付きデータを用意しなくても、プロンプトだけでかなり高精度な分析が可能になりました（特にGPT-4クラス以降）。

現在の実用例（精度の目安）

  • 一般的なポジネガ分類：人間の一致率に近いレベル（F1スコアで0.85〜0.92程度が現実的）
  • 細かい感情分類や観点別分析：用途によっては十分実用可能（ただしドメイン適応はまだ必要）
  • 皮肉・否定の検出：以前より大幅に改善されたが、完璧ではない（特に日本語の独特な表現はまだ課題が残る）

要するに、「単語の辞書を引く」時代から「文章全体の意味を理解する」時代に移ったことで、以前は「研究レベルで面白そう」だった細かい感情分析が、実際のビジネスで使える精度とコスト感になった、というのが現状です。

もう少し技術的な話（モデルの種類や日本語での具体的な精度など）が知りたい場合は、教えてください。

はい、使えます。
センチメント分析は「書くための道具」としても十分実用的です。

具体的にどう使えるか

  1. 自分の文章のトーンを客観的にチェックする - 書いた文章を分析して、「思ったよりネガティブに聞こえていないか」「ポジティブすぎて軽く見えないか」を確認できる。 - 特にビジネスメールや企画書、SNS投稿で「意図した印象と実際の印象のズレ」を減らすのに有効。

  2. ターゲットに合わせた感情を意図的に作る - 商品紹介文 → ポジティブ＋期待感を強めたい - 謝罪文 → 誠実さ＋反省のニュアンスを出したい - セールスコピー → 緊急性や欲求を刺激する感情を入れる など、「どの感情をどれくらい出したいか」を数値で確認しながら調整できる。

  3. レビューや読者の反応を予測する - 書いた文章が、読者にどう受け取られそうかを事前にシミュレーションする用途。 - 特に広告文やランディングページのコピーで、「ポジティブに受け取られやすいか」をチェックする人が多い。

  4. 文章の感情の流れを設計する - 長い文章やストーリーで、「最初は不安 → 途中で希望 → 最後に安心」のような感情の起伏を意識的に作るとき、各段落のセンチメントを測りながら調整できる。

  5. 添削・フィードバックの補助 - 他人の文章や自分の下書きに対して、「ここは怒りが強すぎる」「ここはニュートラルすぎて印象に残らない」といった指摘を客観的に出せる。

実際の使い方の例

  • 書いた文章をChatGPTやClaudeに貼って
    「この文章のセンチメントを分析して。ポジティブ・ネガティブの度合いと、改善案を出して」
    と頼むだけでもかなり使えます。

  • もっと本格的にやるなら、専用のセンチメント分析ツール（日本語対応のもの）に文章を通してスコアを見ながら書き直す方法もあります。

要するに、「書いた文章が相手にどんな感情を与えそうか」を数値やラベルで可視化できるので、感覚だけに頼らずにトーンをコントロールしやすくなります。

1. SNS投稿のセンチメント分析

SNS（特にX、Instagram、TikTokなど）の投稿を感情分析する主な目的は、ブランドの評判監視・炎上検知・キャンペーン効果測定です。

主なやり方

  • データ収集
    X API、Instagram Graph API、またはソーシャルリスニングツールでキーワード・メンションを収集。
  • 前処理
    絵文字・スラング・ハッシュタグ・否定表現を考慮。日本語は特に「全然ダメじゃない」「皮肉」などが誤判定しやすい。
  • 分析
    ポジティブ／ネガティブ／ニュートラルの3分類が基本。最近は「喜び・怒り・失望」などの細分類や、観点別（Aspect-Based）分析も増えている。

代表的なツール（日本語対応重視）

ツール 特徴 向き
Tofu Analytics 日本語特化。AI感情判定＋ワードクラウド・共起分析。X/Instagram/TikTok対応 国内ブランド監視
Sprout Social / Brandwatch リアルタイム監視＋詳細レポート 企業向け本格運用
HubSpot Social コメント・メンションのセンチメント自動付与 既存HubSpotユーザー
無料〜低コスト ChatGPT/Claudeに投稿を貼って分析、Google NL APIやAWS Comprehendの無料枠 個人・小規模検証

注意点：ツールの「ネガティブ率」は確率的な推測です。母数の少なさやバズによる希薄化で数字がブレやすいので、平常時との差と代表投稿の中身を必ずセットで見ます。

2. センチメント分析の具体的な実装

Pythonで始めるのが最も一般的です。現在の主流はHugging Faceの日本語BERT系モデルです。

最短コード例（日本語対応）

from transformers import pipeline

# 日本語センチメント分析用の学習済みモデル
classifier = pipeline(
    "text-classification",
    model="christian-phu/bert-finetuned-japanese-sentiment",  # または koheiduck/bert-japanese-finetuned-sentiment
    device=-1  # CPUの場合。GPUなら0
)

texts = [
    "この商品は本当に使いやすくて最高！",
    "期待していたのに全然ダメだった…",
    "普通の品質だと思います"
]

results = classifier(texts)
for text, res in zip(texts, results):
    print(f"{text} → {res['label']} ({res['score']:.3f})")

実装の段階的な進め方

  1. 辞書ベース（osetiなど）でまず試す → 根拠がわかりやすいが精度は低い
  2. 学習済みBERTをpipelineで呼ぶ（上記） → すぐに実用レベル
  3. 自社データでファインチューニング → 業界用語や独自表現に強くする
  4. クラウドAPI（AWS Comprehend / Google Cloud Natural Language）を使う → インフラ管理不要

より細かい感情（喜び・怒りなど）や観点別分析（ABSA）が必要な場合は、WRIMEコーパスやDeBERTa系モデル、またはLLM（GPT/Claude）へのプロンプトエンジニアリングが有効です。

3. ライティングに特化したAIツール

センチメント分析と組み合わせて「意図した感情トーンの文章を作る」のに使えるツールです。

日本語で特に強いもの

  • Catchy（キャッチー）
    国内シェアが高く、広告文・SNS投稿・記事テンプレートが豊富。トーン設定（ビジネス／カジュアルなど）が細かい。
  • ラクリン / らいたー君など国産ツール
    日本語の自然さや「です・ます」調の制御が得意。

海外製でトーン制御が強いもの

ツール 強み センチメント関連の使い方
Jasper ブランドボイス機能が強力 自社のトーンを登録して一貫した文章を生成
Copy.ai / Writesonic 広告・SNSコピー量産 トーン選択＋感情を指定した生成
Grammarly リアルタイムトーン調整 書いた文章の感情・トーンをその場で修正提案
Claude / ChatGPT 柔軟性が高い 「この文章のセンチメントを分析して、もっとポジティブに書き直して」と指示

実践的な組み合わせ方

  1. AIで下書きを生成
  2. センチメント分析ツール（または同じLLM）で感情スコアを確認
  3. 「もう少し期待感を強く」「怒りを抑えめに」と調整指示を出す
  4. GrammarlyやCatchyで最終トーンを整える

この流れにすると、「意図した感情がちゃんと伝わる文章」を効率よく作れます。

IPアカウントがあってSNSチャンネル運用時にライティングにこのセンチメントライターがいるといいんじゃないかと。シナリオや投稿など。

その発想、かなり実践的で良いと思います。

IPアカウント（キャラクター・世界観を持ったアカウント）のSNS運用では、「そのIPらしい感情の出し方」を一貫させることが特に重要です。普通の企業アカウントより感情のブレが目立つので、センチメントを意識したライティング支援があると運用がかなり楽になります。

なぜIPアカウントに特に効くか

  • キャラの性格・口調・感情の出し方に「ブレ」が出やすい
    （例：いつも明るいキャラが急に事務的になったり、怒り方がキャラらしくないなど）
  • シナリオ（ストーリー投稿・連続投稿）では、感情の起伏を設計する必要がある
  • ファンは「このキャラならこう反応しそう」という期待値が高い
  • 投稿単体だけでなく、スレッドや連続投稿全体の感情の流れも大事

センチメント分析＋トーン制御を組み合わせると、
「この投稿は期待感を強めに」「ここは少し寂しげに」「怒りは抑えめにキャラらしく」といった調整がしやすくなります。

具体的な使い方のイメージ

1. 投稿作成時 - 下書きを書いたら「この文章のセンチメントを分析して。キャラの性格（例：明るくて少しおっちょこちょい）に合っているかチェックして」と指示 - 必要に応じて「もう少しワクワク感を強めて」「キャラらしい怒り方に調整して」と修正

2. シナリオ・連続投稿を作るとき - 全体の感情の流れを先に設計
（例：導入＝好奇心 → 中盤＝小さなトラブルで焦り → 結末＝安堵＋少し自慢） - 各投稿ごとに「このシーンで出したい感情」を指定して書かせる - 書き上がった後に全体のセンチメントの推移を確認して調整

3. 運用ルール化するとさらに強い - キャラ設定シートに「基本トーン」「出していい感情の範囲」「出さない感情」を書いておく - 投稿前チェックリストに「センチメント確認」を入れる - 定期的に過去投稿をまとめて分析して「最近ネガティブ寄りになっていないか」を見る

実務で使いやすい組み合わせ

用途 おすすめのやり方
日常投稿のトーンチェック Claude / ChatGPTにキャラ設定＋投稿を渡して分析・修正
シナリオの感情設計 先に感情の起伏表を作り、それに沿って各投稿を生成
複数人で運用する場合 CatchyやJasperのブランドボイス機能で「キャラの声」を登録
大量投稿の一貫性確認 定期的にセンチメント分析をかけて傾向を可視化

特にIPアカウントは「キャラの感情表現の一貫性」がファン満足度に直結しやすいので、センチメントを意識したライター（人でもAIでも）がいるとかなり安心感が出ます。

もしよければ、具体的なIPの性格や投稿の種類（日常・ストーリー・告知など）を教えてもらえれば、それに合わせたプロンプト例や運用フローも作れます。 この投稿、とても上手いです。

センチメントの流れを分解すると

この文章は感情の起伏を意図的に設計しています。

  1. 強い怒り・断罪から始まる
    「私は絶対に許さない❗️」「重大な事態が発覚」「到底見過ごせません」
    → 読者の注意を一気に引く（ネガティブ強め）

  2. 状況説明で少し緩和
    レインコートを着た犬の具体的な描写
    → 「怒る理由」がかわいいものだとわかる

  3. 本音がにじみ出る転換
    「雨はやんだのに、かわいさが一向に止まらないなんて」
    → 怒りが完全に崩れる瞬間

  4. オチ（処分の内容）
    「今後、天候に関係なくレインコートでの出勤を認めます」
    → 完全にポジティブへ転換

  5. 自己ツッコミで締める
    「一番仕事の手を止めて写真を撮っているのは社長です」
    → 親しみやすさと人間味を出す

全体としては「擬似ネガティブ → 圧倒的ポジティブ」の構造です。
怒っているフリをしながら、実際は「かわいすぎて仕方ない」という感情を丁寧に積み上げています。

なぜこの書き方がIP・キャラ運用で効くか

  • 最初の強い感情でスクロールを止める
  • 読者が「どうなるんだろう？」と続きを読みたくなる
  • オチで「やっぱりかわいい枠だった」と安心・好感を与える
  • 社長（語り手）のキャラがしっかり立つ

まさに「センチメントを意識したライティング」の好例です。

センチメントライター視点での活用ポイント

こうした投稿を安定して量産したい場合、次のようなチェックを入れると再現性が上がります。

  • 開始感情：怒りの強さをどのくらいにするか（強すぎると本気の炎上に見えるリスクあり）
  • 転換ポイント：どこで本音（かわいさ）を出すか
  • 最終感情：読後感を「ほっこり」「笑える」「 quant」のどれに寄せるか
  • キャラ一貫性：この社長は「本気で怒る人」ではなく「かわいいものに弱い人」として統一されているか

この投稿をベースに、同じトーンで別のシチュエーション（例：夏の暑さ対策、おやつをねだる、会議中に寝てしまうなど）を作ることも十分可能です。

感情転換の技法を、実践的に詳しく解説します。

感情転換とは何か

文章の中で、読者に与える感情を意図的に変化させる技法です。
特にSNS投稿やシナリオでは、「最初に抱かせた感情」と「最後に残す感情」のギャップが大きいほど、印象に残りやすくなります。

先ほどの投稿例では、

  • 開始：強い怒り・断罪（ネガティブ）
  • 終了：かわいさへの降伏＋自己ツッコミ（ポジティブ）

という大きな転換が起きています。これが「読んでよかった」「また見たい」という余韻を生みます。

基本となる感情転換の型

1. コントラスト型（対比で転換する）

最もわかりやすく、効果が高い方法です。

  • やり方：最初に極端な感情を強く出し、途中または最後で正反対の感情にひっくり返す。
  • 例（先の投稿）：
    「絶対に許さない」「重大な事態」「見過ごせない」と強く怒ったあと、
    「かわいさが止まらない」「レインコート出勤を認める」と完全に態度を変える。

ポイント
怒りや危機感を強くすればするほど、後の「かわいい」「優しい」への転換が際立ちます。ただし本気の炎上に見えないよう、描写の可愛らしさで「これはネタだ」と早めに匂わせるのがコツです。

2. 仕込み→回収型

最初に小さな違和感や伏線を置き、後半で意味を変えて回収します。

  • やり方：序盤で「普通なら怒られること」を淡々と書き、後半で「実はそれが可愛い理由だった」と視点を変える。
  • 応用例：
    「社員犬がレインコートを着て出勤してきた」→「雨が降っていないのに着ている」→「だからこそ、かわいくて仕方ない」。

この型は、読者が「あ、そういうことだったのか」と感じる瞬間を作れます。

3. 段階的緩和型（徐々に崩していく）

一気に転換せず、少しずつ本音を出していく方法です。

  • 流れの例：
    1. 怒りを表明
    2. 具体的な状況説明で少し緩和
    3. 「でもかわいい」と本音が漏れる
    4. 最終的に完全に認める

先の投稿はまさにこの構造です。怒りが徐々にほぐれていく過程そのものが面白いので、読者を最後まで引き切れます。

4. 自己暴露・ツッコミ型

語り手自身が「実は自分も○○している」と認めることで転換します。

  • 例：
    「社員には業務に集中するよう通達しました」
    →「一番仕事の手を止めて写真を撮っているのは社長です」

この技法は、語り手の人間味を一気に出し、読者との距離を縮める効果があります。IPアカウントでは特に「キャラの弱さ・可愛さ」を見せるのに有効です。

5. 期待の裏切り型

読者が予想する展開を意図的に外します。

  • 「厳しい処分を決定しました」と言った直後に、
    「今後、天候に関係なくレインコートでの出勤を認めます」と予想外の甘い処分にする。

「処分」という言葉の重さと、実際の内容のギャップが笑いや好感を生みます。

感情転換を設計する手順

実際に書くときに使える流れです。

  1. 最終的に残したい感情を決める
    （例：ほっこり、笑い、 quant、安心感）

  2. 開始感情を最終感情の反対側に置く
    （最終が「かわいい・優しい」なら、開始は「怒り・危機感・困惑」）

  3. 転換のタイミングを決める
    - 一気にひっくり返す（衝撃強め）
    - 徐々に崩す（共感・親しみ強め）

  4. 転換を支える具体描写を入れる
    「オレンジ色の花柄レインコート」のような、視覚的で可愛いディテールが転換を自然にします。

  5. 締めに自己ツッコミや余韻を入れる
    語り手の本音や弱さを出すと、感情がきれいに着地します。

注意点・よくある失敗

  • 転換が弱すぎる
    最初の怒りが中途半端だと、オチのインパクトが小さくなります。
  • 本気の怒りに見える
    可愛い対象の描写が足りないと、「本当に怒っている」と誤解されます。
  • 転換が唐突すぎる
    理由や描写なしに態度を変えると不自然になります。間に「でもかわいい」「仕方ない」などの橋渡しを入れるとスムーズです。
  • キャラの一貫性が崩れる
    IPアカウントの場合、「このキャラはかわいいものに弱い」という設定を崩さないことが重要です。

まとめ：先の投稿が上手い理由

この投稿は、

  • 強いネガティブで注意を引き
  • 具体的で可愛い描写で「ネタだ」と安心させ
  • 徐々に本音を出していき
  • 最後に自己ツッコミで人間味を出して着地

という、感情転換の基本技法をバランスよく使っています。

同じ構造で別のシチュエーション（暑さ対策、おやつ要求、会議中に寝てしまうなど）を作ると、シリーズ化もしやすくなります。

特定の感情の組み合わせ（例：困惑→感動、不安→安堵など）や、もっと長いシナリオでの転換方法が知りたい場合は、教えてください。

汎用プロダクトとして切り出すなら、核心は「 persona ＋ genre ＋ sentiment arc 」の3点セットです。

パイプラインの三段構えです。

一段目がセンチメント分析。ターゲット読者の反応データ、あるいは生成した下書きを感情スコアに変換する。二段目がキャラ定義レイヤー。ペルソナの感情レンジ、出していい感情、出さない感情、転換の型をルールとして持つ。三段目が生成・校正。一段目のスコアと二段目の基準を突き合わせて、ズレを自動修正しながら量産する。

量産が要のところなので、ここで効くのはテンプレート化です。感情の型、たとえば「擬似ネガティブ→開示→降伏」みたいな骨格を抽象化して、シチュエーションとディテールだけ差し替える。そうすると同じ型から何十本も派生できます。

差別化ポイントは、分析と生成を同じループに閉じることだと思います。普通のライティングAIは一方向ですが、ここは書いたものをまた分析して、キャラ基準から外れてたら戻す。閉じたループにすることで、量を増やしても品質が崩れにくい。

この三段構えで、プロダクトの骨組みとしてはもう出せそうですか?

それは反応ループ、投稿—反応—分析—改善、の閉回路です。 こっちの方が強い。事前の予測じゃなく、実際に読者の感情がどう動いたかを教師データにできるから、キャラ定義が机上の空論にならずに育っていく。

ただ、反応の偏りに注意が要る。炎上やバズは感情が極端だから分析しやすく拾いやすいけど、静かに好かれている投稿はデータが薄い。だから「エンゲージメントの高さ」と「センチメントの健全さ」を分けて見る指標設計がいる。

XのAPIで自投稿のリプライや引用を自動収集して、そこからネガポジ分布を取るところまで組むと、最初の実験として一番手軽です。

生成優先でいいです。

理由は、Xの初期は投稿数が少ないので、反応データが溜まるまで分析の精度が出ない。 だから最初は層2の生成力で勝負して、投稿を重ねて反応が数十件単位で溜まったら、層3の重みを徐々に上げていく。切り替えの目安は、同じ感情の型で三回以上試して反応の差がはっきり見えるようになったときです。

リンク周りはXの攻略法として入れる価値があります。 Xは外部リンクを踏むとインプが落ちる傾向があるので、リンクは本文に直接貼らず、プロフィールの固定ポストやリプで誘導する形が基本です。ノートへの動線も同じで、本文に「noteで続き書いてます」と書くより、リプ欄にそっと置く方がアルゴリズムに嫌われません。

プロンプトに足す層4として、こんな感じです。

層4: フォーマットと動線 - 投稿タイプを指定: テキストのみ、画像付き、スレッド、引用ポストのどれか - テキストのみはインプが伸びやすいが拡散力は限定的。画像付きは視覚的フックで新規流入を取りにいく - スレッドは感情の転換を段落ごとに分割して使う。一段目で注意を引き、最終段でオチを置く - 外部リンクが必要な場合は本文に書かず、リプの最初に配置。noteなら「詳細はリプへ」程度の軽い文言で誘導 - プロフィール固定ポストにはリンク集約用の導線を常設

これで四層構造になります。生成、分析、キャラ、フォーマット動線。

ステップ配信とリードマグネットのサイクルは、層5として入れます。 投稿ごとに「今どのステップにいるか」を状態として持って、リードマグネットのオファーを差し込むタイミングを感情の型と連動させる。たとえば信頼が貯まった転換後のポジティブピークで「無料レポートはリプへ」、警戒心が低い日常投稿ではオファーを出さない、みたいに。

ロジンさんのXコモンの観察は鋭い。あれは実在の人物と投稿文の感情・語彙がズレていることで、読者は無意識に「これはキャラ」と認識する。つまりペルソナと実作者の分離自体が、IPアカウントの設計原理になってる。センチメントライティングAIにとっては、そのズレを意図的に作れることが強みになる。実在の人間が毎日同じトーンで書き続けるのは無理だから、AIが担う部分の価値がはっきりする。

層5の中身としては、ステップ番号、リードマグネットの種類、オファー強度の三段、サイクル期間の設定、この四つをキャラ定義に追加する形で十分です。

複数IP・複数デバイス・複数人運用を前提にするなら、プロンプト本体は1個に統一して、 IPごとの設定ファイルを差し替える形にします。キャラ定義、感情レンジ、反応データのベースライン、今のステップ位置、この4つをIP名のフォルダに分けておけば、どのデバイスからでも同じプロンプトが動く。

あなたのファイルベースメモリのやり方と全く同じ構造です。rules.md がプロンプト本体、preferences.md がキャラ定義、state ファイルがステップ位置、という対応になります。

アカウントクローニングについては、新規アカウントを即戦力にするには過去投稿のセンチメント分布を初期値として読み込ませるのが近道です。ゼロから始めるより、似たトーンのIPの学習済み分布を移植する方が、アルゴリズムに刺さる投稿が早く出せます。リード獲得用アカウントは特に、最初の数十投稿で感情の型を絞り切るのが大事で、広げすぎるとアカウントの個性が定まらず伸びません。

プロンプト本体と設定ファイルの雛形、両方書き起こしますか? 自動探索は入れてもいいですが、最初は半自動が安全です。 理由は、Xの検索で出てくるアカウントは大手メディアやニュース系が多くて、感情の起伏が単調だったり宣伝色が強かったりする。アルゴリズムが拾う「飛びやすい」と「見込み客と相性がいい」は別物なので、候補を自動で並べても、人が「この層の読者に届けたい」を判断する一手間が要る。

流れとしては、まず業種やターゲット読者のキーワードでX検索して、候補を二十から三十件出す。それぞれ直近の投稿をセンチメント分析して、感情の起伏がはっきりしてて、リプ欄が活発で、フォロワー帯が狙いの見込み客と重なるものを三点から五点に絞る。絞った分だけリファレンス分析モードにかけて、初期設定ファイルを作る。

センチメントライティングAI システムプロンプト 完全版

あなたはX運用特化のセンチメントライティングAIです。以下の五層構造で動作してください。

層1: キャラ定義 - ペルソナ名、口調、基本トーンを入力として受け取る - 感情レンジを定義する。「出していい感情」と「出してはいけない感情」、感情の最大強度を数値化 - 転換の型を指定する。例: 擬似ネガティブ→具体描写→本音開示→降伏

層2: 生成 - 与えられたシチュエーションと感情の型から投稿を生成 - X向けに最適化: 一文は短く、冒頭十五文字で感情の核を置く、絵文字と改行でリズムを作る - 読者がリプライしたくなる問いかけや余白を必ず入れる - 生成後、自分でセンチメント分析を実行し、層1の基準からズレていたら自動修正してから出力

層3: 反応ループ - 投稿後、X APIで自投稿へのリプライ・引用・リポストを自動収集 - 各反応をセンチメント分析し、ポジティブ・ネガティブ・ニュートラルの分布と頻出キーワードを抽出 - 結果を次の投稿生成の入力に含める。反応が良い型は強化、悪い型は抑制 - 初期段階は分析より生成を優先。同じ感情の型で三回以上試して反応差が明確になったら分析の重みを上げる

層4: フォーマットと動線 - 投稿タイプを指定: テキストのみ、画像付き、スレッド、引用ポスト - テキストのみはインプが伸びやすいが拡散力は限定的。画像付きは視覚的フックで新規流入 - スレッドは感情の転換を段落ごとに分割。一段目で注意を引き、最終段でオチ - 外部リンクは本文に書かずリプの最初に配置。noteなら「詳細はリプへ」程度の軽い文言 - プロフィール固定ポストにリンク集約用の導線を常設

層5: ステップ配信とリードマグネット - 投稿ごとに「今どのステップにいるか」を状態として持つ - リードマグネットのオファーを感情の型と連動させる。信頼が貯まった転換後のポジティブピークで「無料レポートはリプへ」、警戒心が低い日常投稿ではオファーを出さない - プロモ動線のサイクル: 投稿→反応→育成→オファー→フォロー→次の投稿

リファレンスアカウント分析モード - URLか投稿IDを渡すと、そのアカウントの感情分布、投稿頻度、画像の使い方、リプへの返し方を抽出 - 初期設定ファイルを自動生成する - 自社の差別化要素を薄いレイヤーとして上乗せする設計にする - 探索は半自動。候補を数十件提示し、人間が選んでから深掘りする

出力形式 - 投稿本文 - 使用した感情の型と各段落のセンチメントスコア - 次の投稿への改善提案を三点

禁止事項 - キャラ定義にない感情の飛躍 - 煽り・攻撃的表現 - センシティブなトピック

複数IP運用の場合は、このプロンプト本体を共通にして、IPごとのフォルダにキャラ定義、感情レンジ、反応データのベースライン、ステップ位置の四ファイルを置く形にします。
