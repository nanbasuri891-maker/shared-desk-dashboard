# AGENT_COLLABORATION_RULES

## 1. 目的

本ルールは、複数エージェント（MUSE / Claude / GPT / Grok など）が共通の実行基盤上で連携する際の、受け渡し順序・形式・停止条件・優先順位を定義する。

個別の EXECUTION_RULES より上位に位置し、経路の曖昧さや勝手な補完を防ぐことを目的とする。

## 案件の起動

- NO3 との壁打ちは素材であり、それだけでは実行の起点にならない（承認・実行指示と区別する）
- 起動は、NO3 が対象の案件・素材・ルートを名指しした実行指示（トリガー）を出したときだけ行う
- トリガーは、対象・素材・ルートの3点を含む1文とする。固定語にしない（音声の誤変換と誤発火の防止）
- トリガーは壁打ちの場で出す。NO3 に二重の操作は求めない（D-008）。Claude への「見て」は読み取りの呼びかけで、起動とは別である
- 壁打ちの相手が MUSE 以外のときは、NO3 がトリガーと同時に壁打ち素材を MUSE へ貼る
- 壁打ち由来の素材は「壁打ち素材」と呼び、既存の「素材」（IP原作素材）と分ける
- トリガー前に、設計・生成を始めない。トリガー前に許されるのは準備だけである
- 取り消し・変更は、追加のトリガーで停止する（MUSE_STATUS の禁止事項に準じる）
- 適用範囲はアイダのみで開始する。他の IP は実測後に広げる
- MUSE の2役割（壁打ち／エージェント連携）については D-021 で定める

### 準備（トリガーの前）

- 準備と起動を区別する。準備は翻訳と構造化であり、副作用を持たない。起動は、依頼文と task JSON の対への切り替え以降で、第2節の工程（設計・生成を含む）を指す
- 準備の順序は、①MUSE が壁打ち素材を原文のまま机に置く、②GPT が翻訳する、③Claude が翻訳を読み、要件と実行要素に構造化する、である。構造化は GPT の翻訳の後に置く
- GPT の翻訳は、質を保ったまま文字数をなるべく少なくする（AI同士のやり取りの文字数の方針、2026-11-05 NO3）。条件の保持は D-018 のとおりとする
- Claude が構造化で読むのは GPT の翻訳を主とし、壁打ち原文は節を指定した参照に限る
- 準備の成果物は results/ に「待機」として置く。依頼文と task JSON の対にはしない。対で置くことは起動そのものであり、GAS が未実行として検知するためである
- トリガーを受けた MUSE は、待機の成果物を依頼文と task JSON の対に切り替え、goals/*/todos/NEXT_<案件>.md に起動を記録する。以降は第2節の順序に従う
- GPT の原案は壁打ち素材を含む素材の1つである。Claude に渡るのは確定版の依頼文だけ（第2節のまま）。準備の翻訳は、起動後に各席向けの翻訳の土台として使う

### 窓（mirror）の除外規則

- 窓（shared-desk-dashboard の docs/mirror）の再生成では、壁打ち原文（wallchat_*.md）を除外する。NO3 の発言の原文は窓に出さない
- knowledge/README.md の wallchat 行は、題名が NO3 の言葉の抜粋のため、窓の再生成時に除く。他の壁打ち由来の派生ファイル（質感の履歴、gate_log の要点行、3席の学んだこと）は、従来どおり窓に含める
- 除外したファイルは、窓の目次にも載せない
- 窓の再生成は、正本への反映と同じ作業で行い、その際にこの除外規則を適用する

### 進行中案件の経過措置

- 週ごとのパッケージを1案件とする。第2週（11/11〜）以降の起動には、NO3 のトリガーを要する
- 適用開始時点で進行中の項目は、次のとおりである。バッチ1の残り（アイダ第1週の各回、11/05〜11/10）、バッチ2、手帳回の反応記録
- 進行中の項目は現在の流れのまま完走させ、本節を遡って適用しない
- 既に置かれた形を正とし、置き直しはしない

### Claude の読み込み量を守る規則

- Claude が読むのは、準備では GPT の翻訳（と節指定した原文の参照）、設計では構造化の成果物と翻訳だけとする。壁打ち素材の原文を丸ごと読ませない
- 依頼パッケージは自己完結にし、読む箇所を節・項目単位で指名する
- 素材ファイルが大きいときは、節で分割して必要な節だけを渡す（上限の数値は実測で決める）
- 全体監査のような広い読みを、1回で Claude に頼まない。観点ごとに分ける
- 再読みが必要なときは、全体ではなく差分だけを渡す
- 読み込み量の実測（2026-11-05、GitHub のファイルサイズによる）：26,170 バイトは「パッケージ構成の合計（仕様の節の読み込みを除く）」であり、「Claude が読んだ量」ではない。版は旧版の構成で、内訳は依頼文 REQUEST_to_claude_aida_no1_2026-11-02 の 6,067 バイト＋素材3件 18,344 バイト（MATERIAL_aida_no1_視座.md 5,110／MATERIAL_aida_no1_雨.md 5,908／MATERIAL_aida_no1_お金.md 7,326）＋CLAUDE_START.md 1,201 バイト＋CLAUDE_STATE.md 558 バイトである
- Claude が実際に読んだ版（REQUEST_to_claude_aida_week1_rest_2026-11-04。第1号の全文を同梱）は、依頼文 10,502 バイト＋CLAUDE_START.md 1,201 バイト＋CLAUDE_STATE.md 558 バイトで 12,261 バイト。素材3件 18,344 バイトを足すと 30,605 バイトになる
- 指名された仕様の節（CONCEPT・OPERATION・CLONE_PACK・Meta運用版・画像生成条件）の読み込み分は未計上である。MUSE が節ごとのバイト数を別行で計上する
- 5時間枠の件の実測（decisions/OPEN.md の1行）が揃うまで、この数値を上限の根拠にしない

## 2. 受け渡しの基本順序

標準の流れは次のとおりとする。

0. GPT（原案：NO3 との壁打ちで実行プロンプトの原案を作成。原案がある案件のみ）
1. MUSE（仕様固め＋GPT との擦り合わせ：正本・仕様との照合を行い、実行内容・参照資料・品質条件・完了条件を確認して確定する）
2. 翻訳層（TRANSLATION_LAYER による指示書化）
3. Claude（下ごしらえ）
4. MUSE（整形・最終形化）
5. 投稿（または次工程への引き渡し）

- GPT の原案は確定版ではない。原案をそのまま Claude に渡してはならない。確定したものだけを渡す。
- 戦略は NO3 の担当である（2026-11-03 変更。GPT を担い手とする戦略試行は終了）。NO3 が決めた戦略を各エージェント向けの形にする工程は、GPT の翻訳担当に含まれる。ただし翻訳の対象は NO3 から渡された範囲に限り、原文を添え、解釈を加えた場合は解釈と明記する。戦略の出力も、MUSE の照合・タスク化を経てから担当工程へ渡す。
- 原案の置き場は `proposals/gpt/`（格納は MUSE）。原案は上書きせず、MUSE の確定版（依頼文）と区別して追跡できる状態に置く。
- GPT は「画像が必要」と明示された場合に、画像生成でも呼び出される。
- 未確定事項や判断が必要な点は、推測で補完せず NO3 に確認する。
- 上記の順序を飛ばす、または逆順で進める場合は、ISSUES に記録した上で NO3 の判断を仰ぐ。

各指示書には必ず「フェーズ（全体の流れの中の位置。前段＝／この仕事＝／後段＝）」を記載する。記載のない指示書は翻訳未完了とみなす。

## 3. 受け渡しの形式

- エージェント間の受け渡しは、必ず翻訳済み指示書を経由する。
- 指示書の場所は、受け取る側の STATE ファイル（CLAUDE_STATE / 該当 STATE など）に明記する。
- 口頭、チャット上の曖昧な指示、または指示書を介さない直接依頼だけで次工程に渡してはならない。
- 指示書は TRANSLATION_LAYER 第5節の形式に従う（タスク名／入力／手順／完了条件／影響確認項目／フェーズ）。

## 4. 止まっているときの扱い

- 影響確認項目で「反映されていない」「条件を満たしていない」と判定された場合、次の工程に進んではならない。
- その場合は NO3 または MUSE に返し、判断を仰ぐ。
- 受け取ったエージェントが勝手に仕様を補完・解釈して進めてはならない。
- 不明点や矛盾がある場合も同様に停止し、ISSUES に記録する。

## 5. GPT の呼び出し条件

- GPT の担当は、エージェント間の翻訳、画像生成、プロンプト設計工程での原案作成（2026-11-03 NO3 決定で改訂）。マーケティング戦略の立案・統括、監査ログの原因分析、成果の評価・達成認定、他エージェントの実行判断は GPT の担当ではない。
- 原案の照合・確定、フェーズの解釈、完了条件の決定を GPT にさせてはならない（MUSE と NO3 の担当）。
- 上記以外の用途で GPT を使う場合は、事前に ISSUES に記録し NO3 の承認を得る。

## 6. 優先順位

1. 共通正本（TRANSLATION_LAYER / COMMON_AGENT_STANDARD / 本 AGENT_COLLABORATION_RULES など）
2. 個別 EXECUTION_RULES
3. その他のローカルな取り決め

- 個別ルール同士が衝突した場合、または共通正本と個別ルールが衝突した場合は、ISSUES に記録して NO3 の判断を仰ぐ。
- エージェントが独自に優先順位を変更してはならない。

## 7. 変更手続き

- 本ルールの追加・修正・削除は、相談を受けた後、まず ISSUES に記録し、NO3 の承認後にのみ行う。
- 緊急対応が必要な場合も、事後速やかに ISSUES に記録し承認を得る。

## 8. 関連文書

- TRANSLATION_LAYER（特に第4節チェックリスト・第5節出力形式）
- 各エージェントの EXECUTION_RULES
- ISSUES（衝突・停止・例外の記録）
