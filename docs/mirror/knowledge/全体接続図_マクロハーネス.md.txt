## 仕事の流れ

1. **アカウントを作りたい**：人間 → ダッシュボード → IP設計担当。リサーチ、ターゲット、IP設計、プロフィール、センチメント分析、制作指示につながる情報を作る。
2. **媒体の運用を始めたい**：IP設計 → マーケティング戦略 → MUSE／Grok。媒体別の運用ナレッジを使い、運用方針・KPI・制作内容を決める。
3. **最近の進捗を確認したい**：ダッシュボード → GitHub の作業履歴・成果物。どこまで進んだか、何が未実施か、次に何をするかを確認する。
4. **もっと改善したい**：Perplexity／Discord → 議事録 → 実行指示 → 担当AI。会話をタスクに変え、実行結果を GitHub に戻す。

## 一言で

**人間の仕事とAIの実行をつなぐ**

仕事を始める → 状況を見る → 話し合う → 指示に変える → 実行する → 履歴に残す → 改善する

## 実装管理への参照

現状との差分、未実装の項目、実装に必要な仕様・接続・担当、進める順番、完了の確認方法は、実装管理情報として分離し、`knowledge/全体接続図_実装管理.md` に置く。この図自体は目標構造として維持し、現状の記述で書き換えない。
