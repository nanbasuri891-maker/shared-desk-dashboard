## 2. IP設計

- **目標構造に対して未実装な点**：工程としての定義が1か所にまとまっていない。入力、成果物の一式、次工程への引き渡し条件が文書化されておらず、独立した作業単位として扱えない。
- **実装に必要な仕様・接続・担当**：
  - 工程定義：入力（基本方針・リサーチ素材）、成果物（IP設計書一式＝コンセプト／ターゲット／プロフィール／運用設計）、完了条件、次工程（運用）への引き渡し条件。
  - 担当の流れ：GPT の壁打ちで原案 → MUSE が正本と照合して確定、という既存の実行フローに載せる。
  - 読者側は仮説として扱い、初動の反響で差し替える（2026-11-01 の合意どおり）。
- **既存の仕組みを使える部分**：新規 IP の立て方の合意（基本方針を集める → プロンプトで IP 企画 → 初動で検証 → 反響で読者側を直す）。既存 IP（フラ／アイダ）のシート形式が成果物の雛形になる。GPT 原案 → MUSE 確定のフローは今日整備済み。
- **進める順番**：工程定義を書く → 実走1件（新規 IP か、既存 IP の作り直しを題材にする）→ 引き渡しまで通す → 工程定義を実走の結果で直す。
- **完了の確認**：IP設計書一式が机に揃い、運用工程がその一式だけを受けて動き始めた記録が1件あること。
- **進捗（2026-11-03）**：工程定義の下書きを作成し机に配置した（`specs/IP設計_工程定義.md`）。残るは実走1件で、題材（新規 IP か既存 IP の作り直し）の決定が要る。

## 3. Perplexity・Discord（音声の入口）

- **目標構造に対して未実装な点**：ダッシュボードから音声入力・音声会議を始められる入口が無い。会話・議事録から実行指示を生成し、GitHub 上のタスクに反映する流れが未設計。Discord は現在テキストの Webhook（送る側）のみ。
- **実装に必要な仕様・接続・担当**：
  - 入口の置き方：ダッシュボードに、音声入力（Perplexity）と音声会議（Discord）への導線を置く。
  - 議事録の取得方法：音声会議の内容をどう文字化するか（録音と文字起こしの手段の選定が必要）。
  - 変換の担当：議事録 → 実行指示 の変換は翻訳層の仕事として MUSE が担う。タスクへの反映形式は既存の tasks/ の形式を使う。
- **既存の仕組みを使える部分**：ダッシュボード（入口の置き場）、翻訳層（会話を実行指示に変える変換は既存の本務）、tasks/ のタスク形式、Discord の Webhook（テキスト側の実績）。
- **進める順番**：入口の導線だけ先に置く → 議事録の取得方法を1つ選んで実測する → 変換 → タスク反映を1件実走する。
- **完了の確認**：ダッシュボードの入口から始めた会話が、実行指示になって GitHub のタスクに反映され、担当工程が動いた記録が1件あること。

## 4. エージェント間通信レイヤー

- **目標構造に対して未実装な点**：エージェント間の依頼・質問・回答を中継する共通の仕組みが無い。現在の経路は相手ごとにバラバラ（Claude は CLAUDE_STATE と依頼文、Grok は提案の戻し経路、GPT は会話経由）で、返答が戻ったかを管理する場所もない。
- **実装に必要な仕様・接続・担当**：
  - メッセージ形式（封筒は不変、状態は別ファイルで管理）と置き場（messages/ に宛先ごとの inbox）。
  - 中継の実装は、Actions の検証拡張と watcher の業務拡張で担う。通信役は内容の判断と書き換えをしない（翻訳は翻訳層の仕事のまま）。
  - 各エージェントの読み込み経路への組み込み（GPT は起動順序、Claude は CLAUDE_STATE、Grok は窓の写し）。
- **既存の仕組みを使える部分**：タスク形式（schemas/）、状態ファイルと state-check、Grok の提案経路と Claude の依頼経路（先行形として既にある）。
- **進める順番**：形式と置き場の確定 → inbox と状態一覧 → watcher への中継業務の追加（watcher 本体の承認が前提）→ 往復1件の実走。
- **完了の確認**：依頼 → 受信 → 作業 → 返答 → 依頼者への回収 の往復1件が、机の記録だけで追える状態になっていること。
- **進捗（2026-11-03）**：設計の下書きと技術調査・構成設計を配置し、全体接続図にも通信レイヤーを追加済み。実装の第1段として messages/ の置き場、スキーマ、message-router ワークフローを構築し、router の実走を確認済み（MSG-0001 の登録を検知し状態一覧を自動書き戻し）。MUSE の受信 watcher（30分ごと、条件は `specs/メッセージwatcher_実行条件.md`）を作成し、手動実行で正常終了を確認済み。残るは GPT 側（方式A）の書き込み実測と返信取得の実証。将来の A2A 対応は視野に入れるが、第1段階は GitHub 中継で実装する。
