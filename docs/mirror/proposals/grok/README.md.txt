# Grok 提案の着地先（X運用の改善提案）

Grok の X 運用の改善提案は、ここに着地する。MUSE 経由の関門は置かない（2026-11-02 NO3 決定）。

## 対象

- X チャンネル運用の改善提案のみ。それ以外の Grok の成果物は、従来どおり各置き場へ。

## 経路

1. Grok は自分の会話の中で、提案を完成形で出す（書式は Grok の席文書「書き戻し経路」のとおり）。
2. NO3 が Grok の共有リンクを MUSE に渡す。
3. MUSE は、判断・整形・要約を挟まず、提案の全文をこのフォルダに格納する。ファイル名は `YYYY-MM-DD_<件名>.md`。
4. MUSE は格納の記録を Discord「美脳」に置く。
5. 採用・不採用の判断は NO3。判断が出たら、MUSE が各ファイルの冒頭の状態（未判断／採用／不採用）を更新する。
6. MUSE は、見立てを Claude がそのまま実行できる投稿仕様パッケージに翻訳する（対象IP／変更する仕様項目／投稿仕様／出力形式／検収の線まで落とす）。判断が要る点は「要判断」として分けて NO3 に上げ、感想のまま実行層へ渡さない。この翻訳は MUSE の整形・最終形化の仕事。
7. MUSE は、翻訳済みパッケージを実行層へ橋渡しする。CLAUDE_STATE に「Grok見立て・翻訳済み（未処理）」として載せ、Claude の次回バッチに渡す。見立てを proposals に置いたままで止めない。
8. MUSE は影響を確認する。Claude の成果物に反映されたか、対象の仕様・生成が変わったか、反響がどうだったか。影響が出ていない見立ては、止まっているものとして NO3 に上げる。判定の条件は、下の「影響確認の検出条件」の3つに固定する。

## MUSE の扱い

- 入口で MUSE は関門にならない。提案の内容を検収対象にせず、運搬する。
- その先の橋渡し（実行層へ渡すこと）と影響の確認までは、MUSE の仕事。
- リンクを受けたら、その日のうちに格納する。

## CLAUDE_STATE への載せ方（4項目で固定）

Grok の見立てを CLAUDE_STATE に載せるときは、見立ての文章そのままではなく、次の4項目で書く。

- 対象：どの X アカウント・どの投稿・どの指標か
- 現状：今何が起きているか（数字があれば数字で書く）
- 仮説：なぜそうなっているか（Grok の現場見立て）
- 提案仕様：Claude が次のバッチで変える具体的な指示。実装可能な一文で書く

## 翻訳の必須工程

- 提案仕様が空欄の見立ては、CLAUDE_STATE に載せない。MUSE が Grok に一言で確認して埋めてから載せる。
- 感想のまま実行層へ流さない。

## 影響確認の検出条件

「止まっている」と判定する条件は次の3つ。1つでも該当したら、止まっているものとして NO3 に上げる。

- Claude の次バッチ成果物に、Grok の提案仕様が反映されていない
- 生成物の仕様（文字数・構成・トーン）が前回から変わっていない
- 投稿後24時間のエンゲージメントが前回比で動いていない

## 窓の再生成

- 着地規約や席文書を更新したら、同じ作業の中で、窓（ダッシュボードのトップと該当する資料ページ）も再生成する。文書だけが新しくて窓が古い状態を作らない。
