# 共有とダッシュボードの絵（2026-10-31、NO3 と確認した構想。ダッシュボードは 2026-11-01 に公開済み）

## 目的
机（GitHub）の基準値と進捗を、NO3 以外の人と AI にも同じ形で届ける。今の GitHub は NO3 の作業場で、現状は NO3 だけが接続している。リポジトリは許可制で、共同作業の相手には、招待と App の許可を付ければ直接読ませることもできる。広く見せる共有は、型と窓の側で行う。案内文は「他の人は見れない前提」で書かない（2026-11-01 NO3 指摘：見れない前提で案内すると、相手の AI が「見れないのが正常」と判断して止まってしまう）。

## 共有範囲の線引き（2026-10-30 夜、NO3「合ってる」で確認）
- 共有する：仕組み一式（席の分け方、格納・実行のルール、グロースハーネスのルールと回路、プロファイルの貯め方の型）。
- 共有する：共同作業の対象（例：フラのプロファイルと進捗）。その人が見れればよく、お互い同じプロファイルを読んで投稿を作れる形。
- 共有しない：NO3 だけの側の生の中身（他プロジェクトのプロファイル実物、アイダの素材指定など）。

## 窓（ダッシュボード）
- 形：静的 HTML を GitHub Pages に置く（Grok 提案、NO3 採用方向）。Muse が机から共有範囲だけを書き出して生成する。
- 鍵：内部でやっているものなので厳密でなくてよい（2026-10-31 NO3）。リンクを知る人が開ける形で可。厳密化が必要になったら Cloudflare Access 等の入り口を足す。
- 注意：静的な写しなので、ページ先頭に更新日時を大きく出す。古い写しを見て動く事故を防ぐ。

## 席の追加
- Grok：ダッシュボード（ゴールとプロファイル）を読んで、X 用の投稿を考える役。読み取り経路はダッシュボードだけ。本体のリポジトリは公開にも接続にもせず、Grok に直接読ませない（机の全部が外部に出るのを避けるため）。X は現場の言葉の解像度が違うため、Grok の案は下書きの位置づけ。公開前に NO3 の目を通す。
- Grok の書き込み：Grok が机へ直接書けるとは考えていない（NO3）。ただし Grok の成果も机に書き込みして残す方がよい、が希望。当面の経路は、人が運ぶか Muse 経由で机に残す。経路の確定は未決定。

## Discord の役割（2026-10-30 の話を含む）
- フラのインサイト受け口：担当者が Discord にインサイトのスクショ／数字を送る（週1回）→ NO3 経由で Muse が机の `results/execution/fura_insights.md` に転記する形（形1）。
- 合図の Discord 化：呼びかけの合図を Discord Webhook で通知する案。送信の実測はまだない。なお Make のベル（合図メール）は NO3 が削除済みで、現行の回路の起点は NO3 の「見て」の呼びかけ。
