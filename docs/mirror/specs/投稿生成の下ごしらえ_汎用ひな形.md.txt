- フェーズ：【前段＝／この仕事＝下ごしらえ／後段＝ を記入】

※ 本ひな形の手順・出力形式が、対象IPの仕様（CONCEPT / OPERATION / CLONE_PACK）とぶつかる場合は、IPの仕様側を優先する。

## 入力（必ず参照する実物）
以下のファイルをすべて読むこと。存在しない・読めない場合は「要確認」として止め、勝手に補完しない。

1. specs/【IP名】/CONCEPT.md
2. specs/【IP名】/OPERATION.md
3. specs/【IP名】/CLONE_PACK.md（人格クローン・パック）
4. 投稿生成条件（手元または specs/ai_coach/ 内の最新版）
5. 過去成功実例：（results/ または該当フォルダの実例名を記入）

## 再現するプロセス段階
プロフ設定 → センチメント前提 → ライティング

（リサーチ・ターゲット再定義・トーンの新規発明は行わない。MUSEが固めた仕様に従う）

## 手順
1. 上記入力ファイルをすべて読む
2. CONCEPT / OPERATION / CLONE_PACK から、今回使う人格・トーン・禁止事項を抽出する
3. 過去成功実例の共通構造を把握する（フックの長さ、具体場面の入れ方、締めの渡し方）
4. 投稿生成条件に従い、以下の形式で投稿文案を1本作成する
   - 対象セグメント（三層のどれか＋状態を一行）
   - 狙う反応（1つに絞る）
   - 冒頭フック（最初の3秒相当）
   - 場面の流れ
   - 締め（行動への渡し方）
   - 使う言葉／使わない言葉
5. 画像が必要な場合は、画像生成用の指示文も併記する（サイズ・画質・参照画像・禁止事項を明記）
6. 完了条件を自己確認してから成果物を出力する

## 完了条件
- 入力ファイルをすべて参照したことが報告に含まれている
- 投稿文案が1本、指定形式で出力されている
- 仕様（CLONE_PACK・投稿生成条件）から外れた要素を追加していない
- 「要確認」事項がある場合は、推測で埋めず明示している
- 成果物を机の指定場所に置ける状態になっている

## 影響確認項目（MUSEが後で確認する）
1. 生成された投稿文が、CLONE_PACKおよび投稿生成条件のトーン・禁止事項を守っているか
2. 過去成功実例の構造的特徴が反映されているか
3. Claudeが「仕様にない要素を勝手に追加していない」か

## 出力形式（厳守）
```
【成果物】
対象IP：
対象セグメント：
狙う反応：
投稿文案：
（本文）

画像指示（必要な場合）：
要確認事項：
参照したファイル一覧：
```

## 禁止事項
- 入力ファイルにない事実・数字・設定を補完すること
- トーンや人格を独自に変更すること
- 仕様が曖昧な部分を「良いと思う方向」で埋めること
- リサーチやターゲット再定義を行うこと
