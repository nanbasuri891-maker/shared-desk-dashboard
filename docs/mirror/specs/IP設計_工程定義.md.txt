# IP設計 工程定義（2026-11-03 下書き）

位置づけ：全体接続図（目標構造）にある「IP設計」を、独立した作業単位として扱うための工程定義。MUSE の下書きであり、実走の結果で較正する。
全体の流れの中の位置：基本方針・リサーチ → **IP設計** → マーケティング戦略 → 運用。

## 1. 工程の目的

アカウントを「誰の・何の・何がどうなる」存在として先に定義し、後段（戦略・運用）が解釈なしに動ける設計書一式を揃えること。設計なしに運用を始めると、反響を見ても「なぜそうなったか」の分析根拠が持てないため、運用より先にこの工程を通す。

## 2. 入力

- 基本方針：ジャンル認定、伸びるリサーチ、発信の基本形など、その IP に適用する方針の実物
- リサーチ素材：対象者の語彙・日常・反応の実物（原文のままのもの）
- 商品と受け皿の事実：何を売るか、導線の受け皿（診断・LINE・商品）の実在
- NO3 の方針決定：IP の方向に関する決定事項

## 3. 工程（順序）

1. **基本方針の収集**：適用する方針と実物を集め、無い項目は「未確定」と明記する（無いものを想定で作らない）
2. **IP企画（仮説シート）**：人格・世界観・言い方・投稿の形をプロンプトで立てる。ここは作り手側の企画なので先に立ててよい
3. **読者側の仮説明記**：読者の像は仮説として分けて書く。実物と初動の反響で差し替える前提を明記する
4. **設計書一式の確定**：成果物（第4節）が揃った状態にする。正本との照合は MUSE が行う
5. **次工程への引き渡し**：引き渡し条件（第5節）を満たしたらマーケティング戦略へ渡す

担当の流れ：原案は GPT との壁打ちで作り、MUSE が正本・仕様と照合して確定する（2026-11-03 の実行フロー方針どおり）。未確定事項は推測で補完せず NO3 に確認する。

## 4. 成果物（IP設計書一式）

- コンセプト：対象の芯（何を扱い、受け手に何が起きるか）、見せ方の原則
- ターゲット：対象者の像（実物に基づく部分と仮説部分を分けて書く）
- プロフィール設計：アカウントの立ち位置、紹介文、導線の置き方
- 運用設計の前提：投稿の形、発信の基本単位、評価の見方（初動 10〜30 投稿でジャンル認定と読者側の仮説を検証する計画を含む）

置き場：対象 IP のシートとして机の specs/ 配下に置く（既存 IP のシート形式を雛形にする）。

## 5. 引き渡し条件

- 成果物一式が揃っている
- 仮説と確定が分かれて書かれている
- 未確定は「要確認」として分離され、実行が止まる項目かどうかが明記されている

## 6. 完了条件（実走時）

- 設計書一式が机に揃い、マーケティング戦略の工程がその一式だけを受けて動き始めた記録があること
- 初動の反響が出たら、読者側の仮説を実物に差し替えた記録を残すこと（差し替えまでがこの工程の較正）

## 7. 既存の合意との関係

- 「想定で作らない」は読者側に掛かる。IP 側（作り手の企画）はプロンプトで先に立ててよい（2026-11-01 の合意）
- ターゲットは枠を埋めて作らない。ペルソナは実物から学習させるのが前提工程
