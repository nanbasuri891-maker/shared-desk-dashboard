# マーケティング戦略エージェント 席設計（2026-11-03）

位置づけ：全体接続図（目標構造）にある「マーケティング戦略エージェント」の席の設計。担い手の決定とは分けて、先に席の仕様を定義する。
土台：`specs/ai_coach/エージェント定義書_マーケティング戦略.md`（役割・判断プロトコル・成果物の形式の正本）。本書は、その定義を机の席・運用経路に落とすための設計であり、定義書と矛盾する場合は定義書を優先する。

## 1. 担当業務

全体の流れの中の位置：IP設計 → **マーケティング戦略** → 運用（MUSE＝Meta／Grok＝X）。

- 現状診断：対象のアカウント・投稿・数字の実物を見て、事実と仮説を分けて出す
- セグメント設計：受け手を三層（①すでに行動した／②知っているけど動けない／③自覚がない）×プラットフォームで切り、層ごとに届く形・届かない形を書く
- コンセプト／世界設計：対象の芯を一行で定義し、見せ方の原則を決める。③中心の案件では「王国」が要るかを判断する
- 動線設計：認知 → 自分ごと化 → リード → 販売 → 継続 の階段を、プラットフォームと受け皿（LINE・診断・商品）に割り当てる
- 発信設計：層と媒体ごとに発信の形を決め、制作指示パッケージに落とす
- 検証と較正：公開後の指標を見て、判断のズレを定義書と正本に書き戻す

やらないこと：投稿本文・画像などの制作そのもの（運用工程の担当）、公開の実行、KPI の決定（KPI は席の配置とフィードバックから生まれるもので、この席が決めるものではない。戦略側は指標の設計と読み取りを担う）。

## 2. IP設計から受け取る情報

- IP設計書一式：コンセプト（対象の芯と見せ方の原則）、ターゲット（読者側は仮説の明記つき）、プロフィール設計、運用設計の前提
- GOAL：その IP／事業の目的、達成条件
- 商品と受け皿の事実：何を売るか、価格と販売条件、LINE・診断・申込先の実在と中身（本人の事実として IP設計側または NO3 から受け取る。戦略側で創作しない）
- 既存の反響データ：過去の投稿と反応（机の results／インサイトの記録）

不足がある場合は、定義書の3分岐（インタビューで取る／構造から予測して「予測」と明示する／要確認に残す）で扱い、推測で埋めない。

## 3. 担当範囲（4つの機能の切り分け）

| 機能 | この席の担当範囲 |
|---|---|
| マーケティング戦略 | 本務。全体の戦略、セグメント設計、動線設計、指標の設計と読み取り |
| コンテンツ戦略 | 本務。発信設計（層×媒体ごとの形の決定、企画の選定） |
| センチメント分析 | 戦略の入力として使う側。読者の感情と欲求の読みをセグメント設計の材料にする。分析の実行そのもの（定常的な段階推定など）は本務ではなく、材料として供給を受ける形にする |
| コピーライティング | 方針と品質条件の指定まで。本文の生成そのものは運用工程の仕事で、この席は制作指示パッケージの「言葉の指定」（使う言葉／使わない言葉）までを担う |

## 4. MUSE（Meta）・Grok（X）への出力と引き渡し条件

- 出力の形：制作指示パッケージ（定義書 第8節の固定形式）。対象アカウント、対象セグメント、プラットフォームと役割、狙う反応、企画と脚本、言葉の指定、素材指示、投稿文の方向、導線、計測、要確認、までを含む
- 置き場：パッケージは机に置く（案件ごとの置き場に一本化する）
- 橋渡し：媒体別の運用への変換は MUSE が翻訳層を通して行う。Meta 向けは MUSE が自工程の実行指示に変換し、X 向けは翻訳層の Grok 形式（対象／現状／仮説／提案仕様）に変換して経路に載せる。戦略の席が運用担当へ直接指示を出す形にはしない
- 引き渡し条件：
  - パッケージの必須項目が埋まっている（要確認は「実行が止まる項目」に限る）
  - セグメント、媒体の役割、狙う反応が明記されている
  - 計測（公開後に見る指標と判断の目安）が書かれている
  - 根拠のない具体・数字が混ざっていない（定義書 第6節の検品を通っている）

## 5. 成果物と実走時の完了条件

- 成果物：現状診断（事実リストと仮説）、セグメント表、動線設計、制作指示パッケージ（案件単位）、検証と較正の記録
- 実走の完了条件：パッケージが MUSE に渡り、運用側が追加の解釈なしに制作に入れたこと。さらに、公開後の計測結果がこの席に戻り、較正が定義書または正本に書き戻されたこと（検証と較正まで回って初めて完了とする）

## 6. 必要なナレッジと参照先

- 定義書と方法論：`specs/ai_coach/エージェント定義書_マーケティング戦略.md`／方法論（クローニングの正解）の13原則
- セグメントの正本：三層セグメントとプラットフォームセグメントの定義（定義書 第2節が参照先）
- SNS の上位原則：D-013（机 decisions/DECISIONS.md）
- eduGate のナレッジ：フォロワーの状態と響く言葉の運用知（Drive「edugate」フォルダと机の索引）
- 事例リサーチ：森部ゆり、おさる等のリサーチメモ／センチメントの実地分析（机 knowledge/research/）
- 対象 IP のシート：specs/ 配下の対象 IP のコンセプト・運用シート
- 反響データ：机 results/ の実行記録とインサイト

## 7. 担い手の候補と比較（決定は NO3）

比較の軸：机の正本を直接読めるか／文脈の蓄積／起動の方法／既存の席との衝突／較正の書き戻しができるか。

| 候補 | 適合する点 | 弱み・衝突 |
|---|---|---|
| Claude | 机を直接読んで書ける（実績あり）。定義書も Claude プロジェクトを器として想定している。バッチで案件単位の作業と書き戻しができる | 現在は「下ごしらえ」の席。戦略は上流の判断の仕事で、席の性格が違う。二役にする場合は担当の切り分けが要る |
| GPT | 壁打ちでの戦略検討の蓄積が一番厚い（この定義書自体もその過程で編まれた）。設計を文書の形に編む力が強い | 机を自律的に読めない（抜粋を渡す運用）。定常の状態管理や書き戻しは MUSE の中継が前提になる |
| MUSE | 机と運用への接続は最短 | NO3 の確定事項として戦略は独立機能であり、MUSE はハブと Meta 運用に絞る前提と衝突する。KPI を決めないという線ともぶつかる |
| Grok | X 側の現場感はある | 窓からしか読めず、戦略は媒体横断なので範囲が合わない |
| 新規の専用エージェント（カスタムGPT／Claude プロジェクトとして新設） | 定義書 第10節の想定そのもので、席と担い手が一対一になる | 立ち上げのコストがかかり、運用実績はゼロから。起動と書き戻しの経路を新規に作る必要がある |

## 8. 残る決定

- 担い手の決定（NO3）。決まれば、席文書（実行ルール／現在の状態）を担い手に合わせて起票し、入出力経路を CLAUDE_STATE 等に接続する
