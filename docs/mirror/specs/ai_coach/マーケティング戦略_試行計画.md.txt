# マーケティング戦略エージェント 試行計画（2026-11-03）

## 目的

GPT を戦略設計の中核として試し、2点を検証する。
1. 戦略の品質：定義書の作法（実物を見る、層で切る、根拠を付ける、補完しない）で戦略が組み立てられるか
2. 引き渡しの成立：原案が MUSE の照合を通り、運用側が追加の解釈なしに制作に入れるか

結果を見て、専用エージェント化が必要かどうかを判断する。

## 題材

1件の IP で実走する。題材は NO3 が決める（MUSE の提案：アイダ）。

## 手順

1. **GPT へ渡す**：GPT_SPEC の起動順序に沿って、定義書、席設計、対象 IP の設計書一式とシートの抜粋、GOAL、商品と受け皿の事実、既存の反響データを渡す
2. **GPT の原案**：現状診断 → セグメント設計 → 動線設計 → 制作指示パッケージ原案、の順で出す。原案は MUSE が `proposals/gpt/` に格納する
3. **MUSE の照合・タスク化**：正本・仕様との照合、定義書の検品（補完ミス／帰属ミス／平均化ミス／固定化ミス）を通し、確定版として担当工程（MUSE 自身の運用、または Claude の下ごしらえ）へ渡す
4. **運用の実走**：確定版で制作・公開まで進める（公開は従来どおり NO3 の承認後）
5. **計測と較正**：公開後の指標を戦略の席に戻し、較正の案を出す

## 評価項目

- 戦略の品質：定義書の検品4点を通過したか／層と媒体の切り分けが一律になっていないか／根拠が実物に基づいているか
- 引き渡し：パッケージの必須項目が埋まっているか／運用側が解釈なしに制作に入れたか／要確認が「実行が止まる項目」に絞れているか
- 工程の負荷：GPT への抜粋の渡し方と MUSE の中継に、どのくらい手間がかかったか（専用エージェント化の判断材料）

## 完了の判定

- 上記の実走1件が公開と計測まで回り、評価項目の記録が机に残っていること
- その記録をもとに、NO3 が専用エージェント化の要否を判断できる状態になっていること
