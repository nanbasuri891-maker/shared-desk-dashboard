## ゴール（NO3の言葉、2026-10-30）

「今のゴール設定は、とりあえず Addness 式のこのルーティングが最初の1ループでも成功すること」

将来的な理想：NO3 はゴールの提示と検収だけを行い、エージェントがゴールを読んで差分を埋め、結果を書き戻す自走が回ること。

## ルーティング（修正済みの実態形、2026-10-30 確認）

- 案件の起動は governance/AGENT_COLLABORATION_RULES.md「案件の起動」に従う（D-020）

1. GOAL を共有の置き場に書く（理想・現状・DoD・制約）
2. 脳（Claude）が GitHub の GOAL と依頼文を読んで取りに来る。NO3 の手番は「見て」の呼びかけだけ（関数呼び出しは存在しない）
3. 脳は型で返す：bottleneck / next_actions / muse_tasks（完成した指示文）/ human_review / goal_updates
4. MUSE は muse_tasks を実行する（受け口はチャット）
5. 結果を GOAL / progress に書き戻す（経路は GitHub API 運搬）
6. NO3 に提示されるのは human_review の項目だけ

## DoD（第1ループ「成功」の定義）

以下の5つ全てに証跡（コミット SHA・返却文面・書き戻し内容）が付いたら成功とする。

1. GOAL が GitHub の ai/ ブランチ上にあり、読み戻して内容の一致を確認できた
2. Claude が型通りの出力（bottleneck / next_actions / muse_tasks / human_review / goal_updates）を返した
3. muse_tasks が MUSE に届き、MUSE が実行して結果を出した
4. 結果が GOAL / progress に書き戻された
5. NO3 に提示されたのが human_review の項目だけだった

## 次のループ（段階別の解消、2026-10-30 NO3 が実行を指示）

### 第2ループ：中身の運搬ゼロで1周回す
- NO3 の動きは、Claude への「見て」の呼びかけ1回だけ。中身は全員が GitHub から読む
- DoD：①RESPONSE_loop2.md が GitHub に置かれた ②NO3 が MUSE へ中身を運んでいない ③書き戻し（progress 追記・GOAL 現状更新）が完了 ④NO3 への提示が human_review だけ

### 第3ループ：MUSE への呼びかけを消す
- 受け口（定期実行ジョブ routing-receiver、1時間ごと）が、NO3 の呼びかけなしに RESPONSE を拾って muse_tasks を実行し、報告が届くことで成立とする
- 第2ループと同時に実証する（NO3 は MUSE へ呼びかけない）
- 失敗条件：RESPONSE 配置から目安2時間たっても報告が来ない場合。その場合は NO3 の呼びかけで代替し、失敗として progress に残す

## 制約

- 未確認の接続を前提にしない（Claude.ai の関数呼び出し、call_muse、Make からの直接起動は使わない）
- 書き込みは ai/ ブランチのみ。main へは書かない
- 検収と、正本への反映は NO3 が決める
- 「できる」は実測済み／設計上可能／未確認を分けて書く。設計上の可能性を実績として書かない


## 管理報告（AUDIT）と呼びかけ（CALL）のルール（2026-10-30 追加）
- Claude の照合・管理の報告は、このフォルダに AUDIT_loop<番号>.md として置く。型は REQUEST_to_claude_loop3.md の指定どおり。
- 受け口は AUDIT を拾って NO3 へ伝達する。AUDIT から実行は駆動しない（実行は RESPONSE の muse_tasks 経由のみ）。
- Claude への呼びかけは CALL.md に記録する（LOOK の書式）。自動起動はしない。

## 席（2026-10-30 確定。2026-10-31 に NO3 が Claude の役割を置き直して更新。同日、並びの確定形を追記）
- MUSE（チャット／窓口、上）：NO3 とのやり取りの相手。全体の概要を把握し、Claude の前作業を受けて整形し、最終の形にする。生成サイクルでは整形前の添削・評価と、投稿前の品質チェックを行い、NO3 の検収へ上げる。連携先に接続して実反応・数字を持ち帰り、机の外への実行（Dify のトリガー、投稿）を担う。机に状態と成果物を置き、運搬が回っているかを証跡と数字で報告する。Claude が読む現状の要約は goals/meta-routing/CLAUDE_STATE.md に置き、作業のたびに更新する
- Claude（整形前作業／机の上の実行環境）：重くて固い前作業を担う。MUSE が整えた仕様・材料・現状要約を机から読み、材料を固め、次の実行指示と照合・フィードバックを机に書く。データの不備があれば、その旨のフィードバックも机に置く。深い照合は、要確認フラグが立ったときと週1回に限る。NO3 と直接の受け答えはしない。動くのは「見て」で呼ばれたときだけで、常時監視はしない
- NO3：ゴールの提示、方向の決定、検収、ルールの決定、正本への反映の決定
- ルールに無いことが起きたら、MUSE は埋めずに判断項目として上げる
- AUDIT の伝達範囲は result と next_for_human のみ。CALL.md の書き手は NO3 または MUSE 窓口で、Claude は読むだけ
- Claude の読み込みは最小にする：読むのは、MUSE が用意した現状の要約と、呼びかけで指定された該当箇所だけ。全量読みはしない（読む量で処理が固まる事象への対策）
- 呼び出し条件に当たったら、MUSE は CLAUDE_STATE.md に要照合フラグを立て、CALL.md に記録する。NO3 への朝の報告には「Claude 呼び出し：あり／なし」を1行入れる
- 定期照合（軽い版）を前倒しする：週1回、MUSE が CLAUDE_STATE.md を更新し、フラグと差分の有無を NO3 へ知らせる。Claude の照合範囲は要約＋フラグ＋差分のみ。連動込みの重い定期照合は、従来どおり自動化の最後の段階に置く
