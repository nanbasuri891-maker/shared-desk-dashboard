翻訳層専用指示書＋チェックリスト（TRANSLATION_LAYER）

正本：机（GitHub shared-ai-workspace）specs/TRANSLATION_LAYER.md ／ この写しは窓から読むためのもの ／ 更新：2026-11-02

文書区分：共通基盤・実行規約 ／ 適用対象：MUSE（主担当）、必要に応じて全エージェント ／ 更新ルール：人間（NO3）の承認を経てのみ改訂する。実行結果で自動書き換えしない。

1. 翻訳層の目的

人間向けの構造説明・構想文書・会話メモを、各AIエージェントが即実行できる手順・指示・成果物形式に変換する層である。

翻訳層は「誰が毎回翻訳するか」の問題ではなく、変換ルールとチェック基準を正本として固定し、担当エージェントが読み込んで動くための仕組みである。

2. 翻訳の基本原則

  1. 抽象度を落とす：概念・方針・思想を、エージェントが今日実行できる具体的な手順に変換する。例：概念「SNSは機会損失を防ぐためのプラットフォームである」→ 手順「X投稿を生成する際、受け手のHARM（Health / Ambition / Relation / Money）のどれを塞ぐ接点かを一文で明示してから生成する」
  2. FACTを区別する：確認済み事実／仮説／未確認事項を必ず分けて書く。不足情報を勝手に補完しない。
  3. エージェント別に分解する：Grok（X運用）は対象・現状・仮説・提案仕様の4項目。Claude（バッチ）は実行可能なタスク指示＋完了条件。GPT（画像）はサイズ・画質・参照画像・禁止事項。MUSE自身は橋渡し先・影響確認項目。
  4. 実行可能性を最優先する：「良い説明」ではなく「今すぐ動ける指示」にする。空欄や曖昧な表現が残っている状態で渡してはならない。
  5. 正本と実行記録を分離する：翻訳結果は実行記録またはCLAUDE_STATE等に書く。翻訳層の指示書自体を実行結果で上書きしない。

3. 翻訳の標準手順（MUSEが従う）

  1. 人間向け文書・会話・見立てを読む
  2. 対象エージェントとGOALを特定する
  3. 概念を手順に落とす（抽象度変換）
  4. FACT・仮説・未確認を明示する
  5. エージェント別の出力形式に合わせる
  6. チェックリストを通す
  7. 合格したものだけをCLAUDE_STATEまたは該当ファイルに載せる
  8. 影響確認の項目を必ず残す（後で検証するため）

4. チェックリスト（翻訳完了の判定基準）

以下をすべて満たした場合のみ「翻訳完了」とする。

  • 抽象度が実行可能な手順まで落ちている
  • 対象エージェントが明示されている
  • 確認済み事実 / 仮説 / 未確認が区別されている
  • 空欄・曖昧表現が残っていない
  • エージェント別の指定形式に適合している
  • 完了条件（何をもって終わりか）が書かれている
  • 影響確認項目（何を見れば反映されたと分かるか）が書かれている
  • 正本を書き換えず、実行記録側に出力している

1つでも未達なら「要判断」としてNO3または担当者に返す。

6. 禁止事項

  • 概念のまま流すこと
  • 不足情報を推測で埋めること
  • チェックリストを通さずに載せること
  • 翻訳結果で本指示書を自動更新すること
  • 「内容はOK」を実行許可と解釈すること

7. 影響確認の標準項目

  1. Claudeの成果物に提案仕様が反映されたか
  2. 生成物の仕様（文字数・構成・トーン等）が変わったか
  3. 投稿後の反響（反応数・質）が動いたか

1つでも「変わっていない」場合は「止まっている」と判定し、NO3に上げる。

  • 各エージェントも必要に応じて参照する
  • 改訂は人間の承認後のみ行う
