GitHub 割り当て（2026-11-01）

前提：並びは縦。MUSE が上で指示塔になり、Claude はその下で作業する。指示は MUSE が「入口ファイル」の形で机に置き、各 AI はそこから辿る。入口が正確なほど、生成側の正本逸脱は起きにくい。 指示の前提：MUSE が指示を出すときは、仕様書・指示書が全部埋まった状態で渡す。指示の完全性は MUSE の責任で、Claude が食い違いを探す状態は作らない。 ブランチの原則：Muse が書くのは ai/ ブランチだけ。main への反映は NO3 の決定時のみ。

IP ごとの割り当て

フラとアイダは別 IP として別々に管理する

  • フラとアイダは、後ろの商品（6レンズ）が共通でも、IP としては別物として扱う。
  • チャンネル＝アカウント運用も別々に管理する。管理単位は「IP × チャンネル／アカウント」。
  • シート、クローン／プロファイル、ペルソナの言葉、参照元の仕上がり、生成条件、投稿サイクル、反響／インサイト、添削・評価は、IP ごとに分けて持つ。
  • フラ側のプロファイルや言葉、フラの参照仕上がりを、アイダ側へそのまま持ち込まない。逆も同じ。
  • アイダ側のビジュアル条件（指先、ネイル、タロット素材、一人称視界など）を、フラ側へそのまま持ち込まない。逆も同じ。
  • 同じ素材を使う場合でも、流用ではなく、対象 IP の仕様に合わせて組み替える。Muse の指示では、最初に対象 IP と対象チャンネル／アカウントを明示する。
  • GitHub 上の置き場も分ける：基準値は specs/fura_world/ と specs/aida/、反響と生成結果も、どの IP のものか分かる形で results/ に残す。

AI ごとの割り当て

NO3

  • 決定、最終検収、ルール変更、正本（main）への反映の決定。机の読みは全域。

Muse（指示塔・運用・検収）

  • 全体の概要把握と指示：各 AI への指示（入口ファイル）を作り、参照先・ブランチ・出力の形まで正確に指定する。
  • チャンネル運用：フラ／アイダの投稿の生成と公開、反響と数字の持ち帰り。アカウントは、この運用が回ることで立つ。
  • 検収・品質チェック：下から戻ってきた成果物を、正本と参照元に照らして検収する。投稿クオリティに達しているかどうかが、そのまま各 AI の評価（KPI）になる。
  • 机への書き込み全般（ai/ ブランチ）：基準値の配置、進捗と結果の書き戻し、他 AI の成果物の転記と格納（参照した条件ファイルと日時を併記）。
  • 軽く保つ：重い作業は下の Claude に回す。線引きは能力ではなく席で決める。MUSE の機能は運用と指示に集中させる。

Claude（作業・下ごしらえ）

  • 常設指示：CLAUDE_STANDING.md（机のルート）。Claude の最初の一手は、このファイルだけを読む。材料は要約と該当箇所まで切って渡し、Claude は固める作業だけに集中させる（パンク対策、2026-11-01）。
  • MUSE の下で、重い作業を担当する：設計の残り、棚卸し、材料固め、調査と構造化、整形前の作業全般。
  • 指示書づくり：作り方（型）が決まった指示書・仕様書は、作る作業も Claude が担当してよい。型を決めるのは MUSE。
  • 仕事は監査ではない。監査・照合の役に固定しない（深い照合は、要確認フラグが立ったときと週1回の範囲だけ）。
  • 読む：全域（goals / specs / knowledge / results）。
  • 書く：Claude の環境は読み取り専用のため、成果物は文面で返し、MUSE が机へ転記する。作業の評価は、MUSE の検収と品質チェックの結果で決まる（CLAUDE_KPI）。

GPT（生成・読み取り専用）

  • 渡し方の正本：GPT_SPEC.md（机のルート、2026-11-01 新設）。GPT は成果物メーカーとして割り切り、仕様は関連箇所の抜粋だけを渡す。前置き・メタ発言の禁止、文字数での制限、AI 臭除去ルールを含む。
  • 窓：前提の確認用に、ダッシュボード（https://nanbasuri891-maker.github.io/shared-desk-dashboard/）も読む。コネクタの無い環境でも、前提だけは窓から揃う形（GPT_SPEC に明記）。
  • 読む：入口ファイル specs/ai_coach/画像生成条件_GPT.md と、その参照先のうち対象 IP のシートだけ（フラなら specs/fura_world/、アイダなら specs/aida/。両 IP を混ぜて読まない）。センチメントライティングでは、机のプロンプトと knowledge/ の言葉バイナリ（生成の材料）も、対象 IP に合わせて読む。
  • 書く：リポジトリには書かない。生成物はチャット側に出し、格納は Muse が行う。
  • 画像生成：サイズと画質は Muse の指示に従う。参照元の仕上がりとの照合は、生成のたびに行う前提。
  • ダッシュボード：本体は NO3 側で作るもので、HTML の作成は GPT が担当している（2026-11-01）。

Grok（X チャンネル運用担当）

  • 読む：ダッシュボード（https://nanbasuri891-maker.github.io/shared-desk-dashboard/ 、公開された共有範囲）だけ。本体のリポジトリは読まない（公開・接続はしない、2026-10-31 NO3 決定）。GitHub の接続ツールが Grok 側にないことは、Grok 自身が申告済み（2026-11-01）。割り当てをダッシュボードから読めたことは同日に確認済み。
  • 書く：リポジトリには書けない（プッシュやリポジトリ操作の手段がない）。成果物はチャットのテキストで出し、机への書き戻しは Muse が行う。X の中身の品質チェックは Grok の席で、公開は NO3 の確認後。
